# M5: Elevated backend, `Cancel`, file streaming, secrets, fetch

**Governing sections:** 5.5 (reserved frames), 5.6, 11 (tier 1 and 2), 11.3.
**Depends on:** M1. Independent of M2 to M4 (test via the spike-style orchestrator or M3 if merged).
**Branch:** `m5-elevated-streaming`

## Scope

1. **`--helper` mode and the `Elevated` backend** (vision 11.3). `Elevated { user }`
   implements `Backend` by lazily spawning `<escalation method> -n -u <user>
   <own exe> --helper` and speaking the primitives (`read`, `write`, `stat`,
   `mkdir_all`, `remove`, `set_mode`, `set_owner`, `copy`, `spawn`) as
   request/response frames over its stdin/stdout. One helper per identity,
   kept for the run, killed on exit. The helper reports its `CmdRan` events
   back through the response so the main process forwards them tagged with
   the identity. The check-mode guard is enforced in the helper too. `System::as_user`
   switches the backend to `Elevated` when the user differs from the process
   user. Sudo password: read from the `Start` frame (new optional field
   `escalate_password`), used with `-S`, zeroized after (`zeroize` crate).
2. **`Cancel`.** A stdin reader thread in the binary sets a flag on `Cancel`;
   `Ctx::step` checks it between steps and fails the run with "cancelled" (no
   step is interrupted mid-apply). The orchestrator sends `Cancel` on ctrl-c
   and waits up to 10 s before killing.
3. **Streaming.** `FileRequest`/`FileChunk`/`FileDenied` and `ctx.local_file`
   returning a temp path (removed at exit), `ctx.local_secret` returning
   `Secret` (zeroized bytes, never on disk), `ctx.fetch` with `FetchChunk`.
   Orchestrator side: paths resolve relative to the workspace root, denied
   outside it. Chunks of 1 MiB; requests may overlap (ids).

## Out of scope / do not touch
Ops, inventory, init. Barrier/run_once/peer_facts stay reserved.
