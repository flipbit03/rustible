# M1: Foundation

**Governing sections of docs/01_VISION.md:** 5.5 (protocol and the four binary
modes), 6.2 (`Op`, `Applied`, step driver), 9 (crates, discovery, shims,
`selected` feature), 10.3 (typed vars), 11 (`Ctx`), 12 (check mode), 14 (error
model).
**Depends on:** nothing. Everything else depends on this.
**Branch:** `m1-foundation`

## Scope

M1 turns the spike-3 SDK and the placeholder crates into the real foundation.
It is deliberately single-threaded: the registry shape, the macro output, and
the runtime entry point are one interface, and splitting them across agents
means agents negotiating it.

1. **Error model** (`crates/rustible-sdk/src/error.rs`), vision 14. Replace the
   enum with an `anyhow`-style opaque error: `pub struct Error(anyhow::Error)`
   or a re-export, `pub type Result<T>`, blanket conversion from any
   `std::error::Error`, `.context()` via a re-exported `Context` trait, and
   `bail!`. Keep `MutationDuringCheck { path }`, `OutputUnavailable { step }`,
   and `CmdFailed { argv, status, stderr }` as concrete types inside the chain
   (`downcast_ref`-able). `Ctx::step` wraps any failure with the step name.
   `Event::Failed` carries the rendered chain plus the `CmdFailed` fields when
   present.

2. **`rustible-macros`** (`crates/rustible-macros`), vision 6.1, 9, 10.3.
   - `#[playbook(hosts = "<name>", vars = <Type>, escalate = <bool>)]` on
     `fn main(ctx: &mut Ctx) -> Result<()>` or
     `fn main(ctx: &mut Ctx, vars: <Type>) -> Result<()>`. `hosts` required;
     `vars` optional; `escalate` optional, default false. Expands to: the user's
     function, renamed to a private `__rustible_main`; a
     `pub fn __rustible_entry(ctx: &mut Ctx, raw_vars: serde_json::Value) -> Result<()>`
     that deserializes `raw_vars` into the vars type (or ignores it when there
     is none) and calls the user's function; a
     `pub static __RUSTIBLE_PLAYBOOK: rustible_sdk::registry::Playbook` holding
     name-independent metadata (hosts, escalate, a `schema: fn() -> serde_json::Value`,
     and `entry`). The word `become` must not appear anywhere (vision 16).
   - `#[vars]` on a struct: derives `serde::Deserialize` and `schemars::JsonSchema`
     (pure Rust), rejects nested struct or map fields with a compile error
     naming the field (flat rule, 10.3), and supports `#[default = <expr>]` on
     fields by rewriting to a serde default function. `Option<T>` fields are
     optional; everything else without a default is required, and the schema
     must say so.
   - Errors: unknown attribute key names the key; `main` with the wrong
     signature names what was expected.
   - Tests: `trybuild` pass/fail cases for each rule above, and an expansion
     test that a marked playbook compiles and `__RUSTIBLE_PLAYBOOK.schema()`
     matches a snapshot.

3. **`rustible-build`** (`crates/rustible-build`), vision 9 and
   `docs/05_SPIKE_PLAYBOOK_DISCOVERY.md`. Port the spike's `build.rs` into
   `pub fn discover()` called from a workspace's generated `build.rs`:
   walk `playbooks/**/*.rs`, parse with `syn` (`full`, and `proc-macro2`
   `span-locations` for error positions), register files containing a function
   with an attribute path `rustible::playbook` or `playbook`, write
   `$OUT_DIR/playbooks.rs` with `#[allow(...)] #[path] mod` lines and a
   `pub static PLAYBOOKS: &[&rustible_sdk::registry::Playbook]`-style registry
   built from each module's `__RUSTIBLE_PLAYBOOK` plus its name. Emit
   `rerun-if-changed=playbooks` and `rerun-if-env-changed=RUSTIBLE_PLAYBOOK`.
   Honour `RUSTIBLE_PLAYBOOK` only when `CARGO_FEATURE_SELECTED` is set;
   otherwise fail with a message explaining the `selected` feature. Errors
   name the file (two markers, parse failure, unknown selection listing the
   available names). Unit-test the scanner on fixture trees, including the
   negative cases from the spike (attribute in a comment or string, unmarked
   files, missing `playbooks/` dir yields zero with a warning).

4. **Runtime and registry** (`crates/rustible-sdk/src/registry.rs`,
   `runtime.rs`), vision 5.5, 11. `registry::Playbook { hosts, escalate, schema, entry }`
   and a `Named { name, playbook }` pair. `pub fn main(playbooks: &[Named]) -> ExitCode`
   implementing the four modes: `--describe` prints JSON
   `{ playbooks: [{ name, hosts, escalate, vars_schema }] }`; `--remote` reads
   the `Start` frame (which gains a `playbook: String` field) and runs that
   entry with `FrameSink`; `--helper` is a stub that exits with "not
   implemented until M5" (do not fake it); a plain local run takes
   `<name> [--check] [-v|-vv] [--json] [--var k=v]...` and uses the `Pretty`
   sink (the sink stays in the SDK until M3 moves it). The `Hello` frame's
   `playbook` field is the registry name, never `argv[0]`. Panics become a
   failed run as today. `HostInfo` gains `escalate_user: String` and
   `connection: String`; `Ctx::as_escalated` uses it (vision 11.3).

5. **Facade** (`crates/rustible`): `pub use rustible_macros::{playbook, vars}`,
   `pub use rustible_sdk::*` under a `sdk` module, `pub mod runtime` and
   `pub mod registry` re-exports so the generated `src/main.rs` can call
   `rustible::runtime::main(PLAYBOOKS)`, and `prelude` re-exporting the SDK
   prelude, `playbook`, `vars`, and `rustible_std` as `std_ops` is fine but
   playbooks import ops as `use rustible_std::{apt, file}` (keep that).

6. **Example workspace** (`examples/workspace/`, listed in the root
   `Cargo.toml` `exclude`, with path dependencies on the crates): the files
   `rustible init` will generate, written by hand for now and copied into M4
   later: `Cargo.toml` (one bin, `autobins = false`, `[features] selected = []`,
   `[build-dependencies] rustible-build`), `build.rs` and `src/main.rs` as the
   two-line shims with the header comment from vision 9, `src/lib.rs` with one
   shared helper, `playbooks/hello.rs` (no vars, logs facts), `playbooks/cadu/mc.rs`
   (port of the spike's `mc` playbook with a `Vars { package: String }` and
   `escalate = true`), `playbooks/cadu/helpers.rs` used by `mc.rs` via
   `mod helpers;` (sibling rule), and `hosts.kdl` plus `rustible.toml` as
   placeholders for M2/M3 (content may be empty). No `README` needed.

7. **Spike orchestrator**: `crates/rustible-cli` keeps working against
   `examples/workspace` instead of `spike-playbook`: change its `--package`
   default and build command to `RUSTIBLE_PLAYBOOK=<name> cargo build --profile
   dist --features selected --manifest-path examples/workspace/Cargo.toml
   --target ...`, and send `playbook` in the `Start` frame. `crates/spike-playbook`
   stays until M3 but is no longer used by the orchestrator.

## Done when

```
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
cd examples/workspace
cargo run -q -- --describe            # JSON: two playbooks, cadu/mc has a schema with "package" required
cargo run -q -- hello                 # pretty output, facts line, ok summary, exit 0
cargo run -q -- cadu/mc --check       # fails cleanly: vars missing (no --var) -> exit 2 with a clear message
cargo run -q -- cadu/mc --check --var package=mc   # would-change or ok, never installs
RUSTIBLE_PLAYBOOK=cadu/mc cargo build --features selected
target/debug/workspace --describe     # exactly one playbook listed
cargo build                           # after the selected build, the IDE-style build is still Fresh for deps
cd ../.. && cargo run -p rustible-cli -- --bin workspace --playbook cadu/mc --host local --escalate --check
```

(Adjust the last line to whatever flag shape the orchestrator ends up with;
the point is that the spike orchestrator still drives the new binary over the
frames.)

## Notes for the implementer

- Reuse `docs/05_SPIKE_PLAYBOOK_DISCOVERY.md`: the `build.rs` there is the
  scanner, tested against twenty hypotheses. Keep its error messages.
- `#[path]`-loaded modules have `mod.rs` semantics (vision 9): `mod helpers;`
  in `playbooks/cadu/mc.rs` loads `playbooks/cadu/helpers.rs`.
- Playbooks are modules of the bin crate; `src/lib.rs` is reached by the
  package name (`workspace::helper()`), not `crate::`.
- Generated identifiers need `#[allow(non_snake_case)]` and clippy allows on
  the registry (`type_complexity`).
- `schemars` is pure Rust; `syn`/`quote`/`proc-macro2` are fine as
  build/proc-macro dependencies (they never reach the target binary).
- The `Applied<T>` deref panic and the check-mode rule are already implemented
  and tested; do not change their semantics.
- `become` is a reserved keyword; the attribute key is `escalate`.
