# M3: The real `rustible playbook run`

**Governing sections:** 3, 5.2, 5.4, 5.5, 9, 10.4, 11 (HostInfo), 14 (rendering failures).
**Depends on:** M1 and M2 merged.
**Branch:** `m3-run`

## Scope

Turn the spike orchestrator into the product CLI, driven by a workspace.

1. **Workspace discovery** (vision 10.4): walk up from cwd to `rustible.toml`;
   `--workspace <dir>` overrides. `rustible.toml` schema: `inventory = "hosts.kdl"`
   (default), `cache_dir = ".rustible"` (default). Everything resolves relative
   to the root.
2. **Commands** (noun first, vision 3): `rustible playbook run <path> [--check]
   [-v|-vv] [--var k=v] [--limit host,group]`, `rustible playbook list`,
   `rustible inventory show|check` (from M2). `playbook create` is M4.
3. **Pipeline** exactly as vision 5.2, steps 1 to 9: locate workspace; describe
   via a host-native build with `--features selected` and
   `RUSTIBLE_PLAYBOOK=<name>` (name derived from the path); cache describe
   output by hash of source plus `Cargo.lock` under `.rustible/`; resolve
   hosts from the attribute's `hosts` (or `--limit`); validate vars for every
   host before anything else and abort with the 10.3 message; connect all
   hosts in parallel (`openssh` for ssh, child process for local), resolving
   `$HOME` and the triple in one probe; one cargo build with all `--target`s,
   `--profile dist --features selected`; sha256; upload if missing to
   `<home>/.cache/rustible/bin/<name>-<hash>` using absolute paths; exec with
   the host's escalation method prefix when the playbook says `escalate`;
   `Start` frame with `playbook`, `HostInfo { name, groups, escalate_user,
   connection }`, merged vars as JSON, check mode, verbosity; stream frames.
4. **Renderer** moves from the SDK to the CLI (`Pretty` deleted from
   `rustible-sdk`). Per-host output is buffered per step so `CmdRan` and debug
   lines nest under their step; hosts are interleaved by whole steps. A
   summary table at the end. `--json` prints the raw frames.
5. **Failures** render per vision 14: step name, chain, and the `CmdFailed`
   fields separately at `-v`. Exit code 2 if any host failed.
6. **Delete the spikes:** `crates/spike-playbook`, the spike-only flag parsing
   in `runtime.rs` if any remains, the `--bin/--package/--host` flags of the
   old orchestrator. Update `docs/02`..`04` headers with one line saying the
   code they describe was replaced in M3 (do not rewrite them).

## Out of scope / do not touch

`init` and `create` (M4). `Elevated`, `Cancel`, streaming (M5). New ops (M6).
The vision doc.

## Done when

```
cd examples/workspace
rustible inventory check
rustible playbook list                                    # hello, cadu/mc
rustible playbook run playbooks/hello.rs                   # hosts from the attribute; local host in hosts.kdl
rustible playbook run playbooks/cadu/mc.rs --check         # local + the ARM VM (both in hosts.kdl), would-change/ok, nothing installed
rustible playbook run playbooks/cadu/mc.rs -v              # real run, escalate from the attribute, apt via sudo on both
rustible playbook run playbooks/cadu/mc.rs                 # second run: ok on both, binaries cached
cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings
```

## Notes
- The spike-2 orchestrator (`crates/rustible-cli/src/{main,transport}.rs`) is
  the pipeline; keep its transport layer and measurements in mind
  (`docs/04_SPIKE_PROTOCOL_SSH.md`).
- The ARM VM is `cadu@cadu-cogram-vm-arm`, passwordless ssh and sudo. It is
  the only remote host allowed in tests.
- `examples/workspace/hosts.kdl` gets `host "local" connection="local"` and
  `host "arm" addr="cadu-cogram-vm-arm" ssh_user="cadu"` in a group `lab`.
