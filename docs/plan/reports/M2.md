## What was built, per brief item

1. **Parsing** (`crates/rustible-cli/src/inventory/parse.rs`). `hosts.kdl`
   through `kdl` 6.5 (`KdlDocument::parse_v2`, KDL 2.0). Top-level `vars`,
   `defaults`, `host`, `group`; inside `group`: `vars`, `members`, `host`,
   `ssh_args`; inside `host`: `vars`, `ssh_args`. Both `vars { a 1 }` and
   `vars a=1` (and both at once). Slash-dash nodes never reach the parser.
   KDL syntax errors are reported with the crate's message, label, and help
   at the diagnostic's line and column. `rustible-cli` gained a lib target
   (`src/lib.rs` exposes `inventory`); the bin stays `rustible`.
2. **Model** (`model.rs`). `Inventory { hosts, groups, defaults, vars, order }`
   (BTreeMaps keyed by name plus file order for output), `Host { name, params,
   vars, group }`, `Group { name, params, vars, members, hosts }`, `HostParams`
   with the seven typed parameters as `Option`s (`Connection` and `Escalate`
   enums, `port: u16`, `ssh_args: Vec<String>`), `VarBag = BTreeMap<String,
   Scalar>`, `Scalar = Str | Int(i64) | Float | Bool | List`. `Scalar::to_json`
   and `bag_to_json` produce the object `Start.vars` and the schema check use.
3. **Load-time errors** (`error.rs`, collected in `parse.rs`). `LoadError {
   file, line, column, message }` displayed as `file:line:col: error: msg`;
   line and column are computed from the byte offset over a char index, so
   multi-byte text does not skew them. Every error from the brief: unknown
   parameter with did-you-mean (`rustible_sdk::vars::did_you_mean`, two
   edits), `addr` on a group or on `defaults`, missing `addr` on an ssh host
   (checked after parsing because `connection` may come from a group or
   `defaults`), duplicate host or group name (names share one namespace, with
   the first definition's line), unknown member with did-you-mean, membership
   cycles (the cycle printed as `a -> b -> a`), wrong parameter type (with
   the value as written), plus: unknown node with did-you-mean, wrong value
   shapes for `vars` (no value, `#null`, properties on a var, nested block, set
   twice), `defaults` or top-level `vars` defined twice, a `group` inside a
   `group`, a name that is not a string. All errors are collected; the file
   is never rewritten.
4. **Resolution** (`resolve.rs`). `resolve(host) -> Resolved { host, groups,
   params: ResolvedParams, vars, sources }`. Parameters: host, nearest group
   outward, `defaults`, built-in (`ssh_user` defaults to the local username
   from `USER`/`LOGNAME`; `escalate_user` to `root`). Vars: top-level, groups
   outermost to innermost, host. `Sources` records the origin of every
   parameter and var (`all`, `group X`, `host`, `defaults`, `built-in`) and
   every value that was overridden, which is what `inventory show` prints
   under "overridden". Sibling conflict at equal distance without a nearer
   override is an error naming the host, the key, and both groups, with the
   fix from vision 10.3 in the message; it is checked for every host at load,
   so `inventory check` finds it. `select(name)` returns the one host or a
   group's hosts through the transitive closure, in file order, or an
   `UnknownName` with a suggestion. `group_levels` and `groups_of` expose the
   distance structure for M3.
5. **Vars validation** (`validate.rs`, over `rustible_sdk::vars`). `validate(&VarBag,
   &schema) -> Vec<VarError { var, severity, message }>` per host: required
   missing (error), wrong type (error, through the SDK's `type_mismatches`,
   which follows `$ref` into `$defs`, `anyOf` for `Option`, `enum`, `items`,
   integer `format` and bounds), `type: object` property (error, the M1
   flatness rule), undeclared var (warning with did-you-mean). A `null`
   schema means "no vars", nothing is checked. `format_vars_report(target,
   is_group, playbook, inventory_file, &results)` renders the multi-host
   report byte for byte as vision 10.3, with one "Add `x` to hosts b and c"
   hint per missing var, and a single-host variant. The SDK gained
   `missing_required`, `type_mismatches`, and `did_you_mean` as structured
   helpers so the runtime's `Start` re-validation and this pre-check share
   one implementation.
6. **CLI** (`main.rs`, `show.rs`). `rustible inventory show <host> [--file
   hosts.kdl]` prints header with groups, then `parameters`, `vars`, and
   `overridden` tables with sources, aligned. `rustible inventory check
   [--file hosts.kdl]` prints every load error to stderr, a `file: N errors`
   footer, exit 1; on success `hosts.kdl: ok (7 hosts, 5 groups)`. Vars
   validation against playbooks is not wired (needs M3's `--describe` call).
   The spike orchestrator's flags moved under `rustible run` unchanged.

## Deviations

- **`inventory check` does not validate vars against playbooks.** The brief
  says "until M3, `check` validates the file only"; that is what it does. The
  whole pre-check path (`select` + `resolve` + `validate` + `format_vars_report`)
  is exercised in tests against a fixture of the `--describe` shape.
- **Sibling conflicts also cover parameters** (vision only decides vars).
  Recorded in `DECISIONS.md`.
- **`ssh_args` has a property form** for a single argument next to the child
  node form for a list; a KDL property cannot hold a list. Recorded.
- **Group distance is shortest path** with nesting and `members` both at
  distance 1; the vision says "nearest group outward" without defining
  distance for `members`. Recorded.
- **`rustible-cli` has a `run` subcommand** instead of the spike's flat
  flags, so `inventory` and M4's `init` / `playbook create` fit. M3 replaces
  `run` with `playbook run`.
- The merge of `main` (PR #2) into this branch kept both sets of subcommands
  under M4's `Cmd`/`cmd` naming and both manifest additions (`kdl` here,
  `tempfile` dev-dependency there).

## The `--describe` schema shape consumed

`validate` takes the `vars_schema` value of one playbook entry of the
`--describe` document M1 defined:

```json
{
  "protocol": 2,
  "playbooks": [
    {
      "name": "cadu/mc",
      "hosts": "lab",
      "escalate": true,
      "vars_schema": {
        "$schema": "https://json-schema.org/draft/2020-12/schema",
        "title": "Vars",
        "type": "object",
        "properties": {
          "package":      { "type": "string", "description": "The apt package to ensure." },
          "update_cache": { "type": "boolean", "default": false },
          "port":         { "type": ["integer", "null"], "format": "uint16", "minimum": 0, "maximum": 65535 },
          "retries":      { "type": "integer", "format": "uint32", "minimum": 0, "default": 3 },
          "mode":         { "$ref": "#/$defs/Mode" }
        },
        "required": ["package"],
        "$defs": { "Mode": { "type": "string", "enum": ["fast", "safe"] } }
      }
    },
    { "name": "hello", "hosts": "local", "escalate": false, "vars_schema": null }
  ]
}
```

What the check reads, and nothing else: `properties` (declared names; each
property's `type` as string or array, `enum`, `const`, `items`, `anyOf` /
`oneOf`, `format` and `minimum` / `maximum` for integers, and `$ref` into
`$defs` or `definitions`), `required` (missing-var errors), and whether a
property resolves to an object (flatness error). `default`, `description`,
`title`, and `$schema` are ignored. `null` means the playbook takes no vars.
A field is required iff it is in `required`; `Option<T>` fields appear as
`"type": ["T", "null"]` or an `anyOf` with a `null` branch and are never
required.

For M3 the wiring is: for each playbook entry, `inv.select(hosts)`, then per
host `inv.resolve(name)` and `validate(&resolved.vars, vars_schema)`, collect
into `HostResults`, and print `format_vars_report(hosts, is_group,
"playbooks/<name>.rs", "hosts.kdl", &results)` when it is `Some`. Warnings
(`Severity::Warning`) are informational. `bag_to_json(&resolved.vars)` is the
`Start.vars` value; `resolved.params` carries the connection settings for the
transport, and `resolved.groups` fills `HostInfo.groups`.
