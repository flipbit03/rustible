## What was built, per brief item

1. **`--helper` mode and the `Elevated` backend** (`crates/rustible-sdk/src/backend/elevated.rs`,
   `system.rs`, `runtime.rs`). `Elevated { user }` implements `Backend`; every
   primitive (`read`, `write`, `stat`, `mkdir_all`, `remove`, `set_mode`,
   `set_owner`, `copy`, `spawn`) is a `HelperRequest { checking, op }` frame
   on the helper's stdin answered by a `HelperResponse` on its stdout, framed
   with `protocol::{read_frame, write_frame}`. The helper is spawned on first
   use as `<method> -n -u <user> <current exe> --helper` (method from the new
   `HostInfo.escalate_method`, default `sudo`; `doas` supported; `none`
   refuses), one per identity for the whole run, shared by every `System`
   clone through an `Escalation` registry, closed on drop (stdin closed, two
   second wait, then kill). `--helper` is `serve_helper`: a `Local` backend in
   a request loop that also refuses mutations when the request says the
   caller is in `check`, so the mutation guard holds on both sides. Errors
   carry the errno so `NotFound` survives the round trip; a helper that dies
   (sudo refused, crash) is reported with its exit status and the tail of its
   stderr, which is otherwise forwarded line by line. `System::as_user`
   switches the backend to the helper when the user differs from
   `facts.user`, back to `Local` when it is the same, and keeps the old
   `sudo -n -u` command prefix only on `Fake` systems. `CmdRan` events keep
   flowing from the main process's `Cmd::run`, tagged with the identity,
   because the helper only executes; the pretty renderer shows `as root`.
   Sudo password: `Start.escalate_password: Option<Secret>` (serde default),
   fed with `sudo -S -p ''` only after `sudo -n -u <user> true` was refused
   (see Decisions), zeroized on drop; the spike CLI takes it from an
   environment variable named by `--escalate-password-env`.
2. **`Cancel`** (`channel.rs`, `ctx.rs`, `runtime.rs`, CLI `main.rs`,
   `transport.rs`). In `--remote` mode a stdin reader thread feeds every
   frame after `Start` into the `Channel`: `Cancel` sets a sticky flag with
   its reason; EOF closes the inbox and also cancels. `Ctx::step` checks the
   flag before `check` (the step is not started, error "step `x` not
   started: cancelled: ...") and between `check` and `apply` (the step is
   reported `Failed` with the reason and nothing is applied). The
   orchestrator turns ctrl-c (`tokio::signal::ctrl_c`) into a `Cancel` frame
   to every host, then waits ten seconds for the binary to stop between
   steps and kills it otherwise: the local process group, or over SSH every
   process naming the binary's cached path plus their children. For ctrl-c
   to reach only the orchestrator, local children start in their own process
   group and the SSH transport uses openssh's `native-mux` feature (no
   per-command `ssh` client in the terminal's foreground group).
3. **Streaming** (`protocol.rs`, `stream.rs`, `channel.rs`, `ctx.rs`, CLI).
   Protocol 3 adds the reserved frames from vision 5.5: `FileRequest`
   (up), `FileChunk`/`FileDenied` (down), `FetchChunk` (up), correlated by
   request id; requests may overlap (the inbox queues frames per id).
   Chunks are 1 MiB; byte fields travel as base64. `ctx.local_file(path)`
   writes the chunks to `<temp dir>/.rustible-XXXX/<req>/<file name>`,
   removed when the run's last `Ctx` drops. `ctx.local_secret(path)` returns
   a `Secret` (a `Zeroizing<Vec<u8>>`, redacted `Debug`, never on disk: the
   chunks go straight into the zeroized buffer and every frame body is
   zeroized after decoding). `ctx.fetch(remote, dest)` reads through `sys`
   and sends `FetchChunk`s; `dest` with a trailing slash lands at
   `<dest>/<host>/<file name>`. Orchestrator side: `stream::WorkspaceFiles`
   resolves paths relative to the workspace root and denies absolute paths,
   `..`, symlink escapes, missing files, and non-files with a reason the
   binary reports verbatim; fetched files are written in order under the
   root. A local run (no `--remote`) serves files from the working
   directory through the same type. Example playbooks
   `examples/workspace/playbooks/cadu/{escalation,streaming,slow}.rs`; the
   50 MB `files/big.bin` and `files/secret.txt` are generated by the
   done-when script and gitignored, as is `out/`.

## Protocol version 2 to 3

`PROTOCOL_VERSION` goes from 2 to 3. What changed on the wire: four new
frames (`Down::FileChunk`, `Down::FileDenied`, `Up::FileRequest`,
`Up::FetchChunk`), the optional `Start.escalate_password`, and base64 for
byte fields. Compatibility story:

- The orchestrator compares `Hello.protocol` with its own constant and stops
  with "protocol mismatch: orchestrator speaks 3, binary speaks N; rebuild
  the workspace against this rustible" before sending anything but `Start`.
  A stale cached binary on a target is therefore rejected, never driven with
  frames it cannot parse. Vision 5.5: a mismatch means "rebuild", never
  silent breakage.
- `Start.escalate_password` has `#[serde(default)]`, so a version 3 binary
  accepts a `Start` from an orchestrator that does not send the field; it is
  the new `Down` variants a version 2 binary would fail to deserialize, and
  the new `Up` variants a version 2 orchestrator would choke on, that force
  the bump.
- Helper frames (`HelperRequest`/`HelperResponse`) are not versioned: both
  ends are always the same binary (the helper is `<own exe> --helper`), so
  the new `HelperOp` variants from the merge need no bump.
- The reserved tier 3 frames (`BarrierWait`, `BarrierRelease`, `PeerFacts`)
  are still not defined; adding them will be the next bump.

## Decisions

Recorded in `docs/plan/DECISIONS.md` under rule 2.3:

- `HostInfo.escalate_method` rather than a `Start` field.
- Base64 for byte fields on the wire; zeroized frame bodies.
- EOF on stdin in `--remote` mode cancels the run.
- `fetch` to a trailing-slash destination adds `<host name>/`.
- `fetch` reads the whole file through `sys` (64 MiB cap when escalated).
- Password fed to `sudo -S` only after `sudo -n` was refused; `doas` with a
  password is an error.
- `Fake` systems keep the sudo command prefix on `as_user`; real ones do not.
- `native-mux` SSH transport and local process groups so ctrl-c does not
  kill children before `Cancel` is sent.
- Remote kill by matching the binary's cached path plus children.
- Local runs serve `local_file` from the working directory.
- `Cancel` between `check` and `apply` fails the step.
- (merge) `Elevated` proxies main's seven new `Backend` primitives with two
  new `HelperResponse` variants; `stat_follow`, `read_link`, `read_dir` count
  as reads for the check-mode guard.

### One bug the rework found

`Transport::kill` killed the shell that was doing the killing. The
remote kill takes its candidates from `pgrep -f <the binary's path>`,
and the shell running that loop has the path on its own command line, so
it matched itself: it died partway through the loop, and whether the
real targets died first came down to pid order. The visible symptom was
the ARM host being closed with "FAILED: the remote process has
terminated", the mux channel's view of its own command being killed,
rather than with the cancellation. `/proc/<pid>/exe` is now the filter:
only processes the kernel says are running the binary get signalled,
with their children. `kill_script` has a unit test for the guard
preceding the kill and for the path staying quoted. The same flaw was in
the pre-merge branch and in the old done-when script's leftover check,
so it predates the merge; the shipped CLI is where it got caught,
because M3's ControlMaster session surfaces the error instead of
swallowing it.

### `Local::spawn`'s stdin fix reaches the escalated path

PR 16 changed `Local::spawn` to feed a child's stdin from a thread the
parent joins after the child exits, because the previous inline write
deadlocks against a child that fills its output pipe before reading. The
helper does not write to a child's stdin itself: `HelperOp::Spawn` calls
`local.spawn(&spec)`, so an escalated `ctx.sys().cmd(..).stdin(..)`
inherits the fix with nothing to mirror. A test now pins that through
the helper boundary, running a 1 MiB stdin against a child that writes
1 MiB before reading a byte. It is bounded by a channel timeout, so a
regression fails in thirty seconds rather than wedging the suite;
reverting `Local::spawn` to the inline write fails it and hangs
`local`'s own equivalent test, which has no bound.

The rest of PR 16's SDK surface needed nothing: the `Backend` trait,
`CmdSpec` and `spawn`'s signature are unchanged, so `Elevated` proxies
no new variants. `Escalation` and `Planned` sit side by side in
`system.rs`.
