# M1 report: Foundation

**Branch:** `m1-foundation`. **Run:** unattended run 1, 2026-09-08. **Brief:** `docs/plan/M1.md`.
**Done-when log:** `docs/plan/logs/M1-done.txt` (local leg), `docs/plan/logs/M1-arm.txt` (ARM VM leg).

## What was built, per brief item

1. **Error model** (`crates/rustible-sdk/src/error.rs`). `Error` wraps
   `anyhow::Error`; blanket `From<E: std::error::Error>`; `Context` trait with
   `.context()`/`.with_context()` on results and options; `bail!` and
   `ensure!`; `chain()` renders outermost-first. Typed signals kept as
   concrete types inside the chain: `MutationDuringCheck`, `OutputUnavailable`,
   `CmdFailed { argv, status, stderr }`, plus `IoAt` and `SpawnFailed`.
   `Ctx::step` wraps failures with `` step `<name>` ``; `Event::Failed` now
   carries the chain and a `FailedCmd` mirror of the command failure, and the
   renderer shows the command and its stderr at `-v`. Three unit tests.
2. **`rustible-macros`.** `#[playbook(hosts, vars, escalate)]` renames the
   user's `main` to `__rustible_main`, emits `__rustible_entry(ctx, raw_vars)`
   and `pub static __RUSTIBLE_PLAYBOOK: registry::Playbook`. `#[vars]` adds
   `serde::Deserialize` and `schemars::JsonSchema` derives through
   `::rustible::sdk::__private` (no serde dependency in the workspace),
   rewrites `#[default = expr]` into a serde default function, rejects map and
   tuple fields. Errors name the key, the expected signature, or the field.
   Seven `trybuild` cases (two pass, five compile-fail with pinned stderr).
   Field doc comments become schema descriptions for free.
3. **`rustible-build`.** `discover()` for the generated `build.rs`; `scan`,
   `select`, `render` as testable pure functions. Errors: parse failure with
   file:line:col, two markers naming the functions, unknown selection listing
   the available names, `RUSTIBLE_PLAYBOOK` without `CARGO_FEATURE_SELECTED`
   refused with an explanation. Missing `playbooks/` dir warns and registers
   zero. Seven unit tests on temp fixture trees, including the negative cases
   from the discovery spike.
4. **Runtime and registry.** `registry::{Playbook, Named, describe_all}`;
   `runtime::main(&[Named])` with `--describe`, `--remote` (reads `Start`,
   which gained a `playbook` field, and replies `Hello` with the registry
   name), `--helper` (exits 3 with "not implemented until M5"), and the local
   run `<name> [--check] [-v|-vv] [--json] [--var k=v]`. `HostInfo` gained
   `escalate_user` and `connection`; `Ctx::as_escalated()` added. Exit codes:
   0, 2 failed, 3 misuse. The pre-macro `runtime::run` is kept for
   `spike-playbook` (deleted in M3).
5. **Facade.** `rustible::{sdk, std_ops, playbook, vars, registry, runtime, prelude}`.
6. **Example workspace** at `examples/workspace/` (excluded from the repo's
   Cargo workspace): manifest with the `selected` feature and the `dist`
   profile, the two shims with header comments, `src/lib.rs` with a shared
   helper reached as `workspace::greeting()`, `playbooks/hello.rs`,
   `playbooks/cadu/mc.rs` with a `Vars { package, update_cache }` and
   `mod helpers;` resolving to the sibling `cadu/helpers.rs`, placeholder
   `hosts.kdl` and `rustible.toml`.
7. **Spike orchestrator** builds the example workspace with
   `RUSTIBLE_PLAYBOOK=<name> cargo build --profile dist --features selected
   --manifest-path`, takes `--playbook` and `--var`, sends `playbook` and vars
   in `Start`, and caches per playbook on the target.

## Verified

Everything in the brief's done-when block, verbatim, in `M1-done.txt`:
`--describe` lists both playbooks with the schema marking `package` required
and `update_cache` defaulted; `hello` runs; `cadu/mc --check` without vars
fails with "vars: missing required var `package`" and exit 2; the selected
build's binary lists exactly `cadu/mc`; a plain build afterwards has every
dependency Fresh; `RUSTIBLE_PLAYBOOK` without the feature is refused; the
orchestrator drives the new binary over frames against `local`.

## Deviations and findings

- **The example workspace does not inherit the repo's `[profile.dist]` or
  `.cargo/config.toml`** because it is detached (`[workspace]` table). The
  profile was added to its manifest. **For M4:** `rustible init` must
  generate both the `dist` profile and the per-target `rust-lld` linker
  config; a workspace outside this repo has neither. Recorded in
  `DECISIONS.md`.
- **Flatness of vars is enforced syntactically only for maps and tuples.** A
  nested struct is indistinguishable from an enum by name in a proc macro. The
  orchestrator's schema validation (M2/M3) must reject `type: object`
  properties. Recorded in `DECISIONS.md`.
- **trybuild cases wrap the playbook in `mod playbook { .. }` with a real
  `fn main`**, because the macro renames `main` and trybuild compiles cases as
  binaries. This mirrors reality (playbook files are modules).
- **`--var` values that parse as JSON are taken as JSON** (`--var port=22` is
  a number, `--var name=x` a string); the same rule is proposed for the CLI.
- The ARM VM was unreachable at the first orchestrator attempt (connect timed
  out; it had answered 20 s cold minutes earlier). Retried per protocol
  section 5; result in `M1-arm.txt`.

## Shapes M2 to M6 depend on

- `--describe` JSON: `{ "protocol": 1, "playbooks": [ { "name", "hosts", "escalate", "vars_schema": <JSON Schema or null> } ] }`. The schema is
  schemars 1.x output: `properties`, `required`, `default` per property,
  `description` from doc comments, `type`.
- `Down::Start { run_id, playbook, host: HostInfo { name, groups, escalate_user, connection }, vars: Value, check_mode, verbosity }`.
- Registry: `rustible::registry::Named { name, playbook: &Playbook { hosts, escalate, schema: fn() -> Value, entry: fn(&mut Ctx, Value) -> Result<()> } }`.
- Generated file names: `__pb_<name with / - . replaced by _>` modules; `PLAYBOOKS` static.

## Self-review

`code-review` at effort high on the branch (eight finder passes plus a
consolidation). Ten consolidated findings; all confirmed by reproduction
except where noted. Fixed in commit "apply self-review findings":

1. Selected builds parsed every sibling, so a syntax error in an unselected
   file blocked a selected run (contradicting section 9). Now selected mode
   reads only `playbooks/<name>.rs` and emits `rerun-if-changed` for that file
   alone, which also stops sibling edits from rebuilding a selected binary.
   Verified end to end with a broken `wip.rs` in the example workspace, plus a
   unit test.
2. `#[default = "mc"]` on a `String` field did not compile (`&str` literal).
   String literals now go through `Into`, and a bare value for an `Option<T>`
   field is wrapped in `Some`. Covered by the `pass_with_vars` trybuild case.
3. Generated module identifiers could collide (`a-b` and `a_b`) or be invalid
   (`my playbook.rs`). Now sanitized plus a short hash of the exact name.
4. `walk()` followed symlinks with no cycle guard. Symlinks are skipped with a
   cargo warning; tested with a self-referential link.
5. A failed command's stderr was rendered up to three times. `CmdFailed`'s
   message is now `<argv> exited <status>`; stderr rides once on the `Failed`
   event and prints once at `-v`.
6. `Start.playbook` was a required field with no version signal. Protocol
   version is 2, the field is serde-defaulted (empty means "the only
   playbook"), `Failed.cmd` is serde-defaulted too, and the CLI refuses a
   `Hello` whose protocol or playbook name does not match.
7. `local()` silently kept the last of two positional names. Rejected now.
8. Mode flags were only recognized as the first argument. Any position now.
9. The workspace advertised `rust-version = "1.85"` while using let-chains
   (1.88). Raised to 1.88.
10. **Dismissed: `#[serde(deny_unknown_fields)]` on vars.** The reviewer wanted
    typos in var names to fail. Vision 10.3 makes a host's var bag shared by
    every playbook that targets the host, so undeclared keys are legitimate.
    Instead the runtime warns on every undeclared key and adds a did-you-mean
    when one is within two edits of a declared name (verified:
    `--var update_cach=true` warns "did you mean `update_cache`?"). Recorded in
    `DECISIONS.md`.

Reuse and simplification findings from the finder passes, also applied: one
`vars::parse_var` for the runtime and the CLI, `event::stdout_sink`,
`CmdFailed` serialized directly instead of a mirror struct, `HostInfo`
struct-update syntax in the CLI, `tempfile` from the workspace dependency
table, the spike compat `runtime::run` and its thread-local trampoline
deleted (the spike binaries register a static `Playbook` and call
`runtime::main` directly), dead error API (`inner`, `from_anyhow`, the
`From<Error> for anyhow::Error`) removed, trybuild fail cases no longer pin
an unrelated rustc warning, the example workspace carries its own
`.cargo/config.toml`.

Noted, not changed in M1: the spike orchestrator ignores the attribute's
`escalate` (the real CLI reads `--describe` in M3); alternating between two
playbooks re-links the selected binary each time because the `selected`
feature keys one output directory (recorded in `DECISIONS.md` as a design
observation for M3 to weigh a per-playbook artifact cache against disk).
