# M3 report: the real `rustible playbook run`

**Branch:** `m3-run` (merged with `main` at eca57dd). **Run:** unattended run 1, 2026-09-08, two passes. **Brief:** `docs/plan/M3.md`.
**Done-when log:** `docs/plan/logs/M3-done.txt`.

## What was built, per brief item

1. **Workspace discovery** (`crates/rustible-cli/src/workspace.rs`).
   `Workspace::discover` walks up from the current directory to
   `rustible.toml` (vision 10.4); `--workspace <dir>` (global flag) overrides
   and must name a directory holding the file. `Config` is the file's schema:
   `inventory = "hosts.kdl"` and `cache_dir = ".rustible"`, both defaulted,
   unknown keys refused with the key named. `inventory_path`, `cache_dir`,
   `playbooks_dir`, `manifest` resolve against the root; `playbook_name`
   turns what the user typed (a path relative to the cwd, an absolute path,
   or a registry name like `cadu/mc`) into the registry name through
   `rustible_build::name_of`, refusing files outside `playbooks/`.
2. **Commands** (`main.rs`). `rustible playbook run <path-or-name> [--check]
   [-v|-vv] [--var k=v]... [--limit host,group] [--json]`, `rustible playbook
   list` (the build script's scan, name and path per line), `rustible
   playbook create` (M4, unchanged), `rustible inventory show|check` (M2;
   `--file` is now optional and defaults to the workspace's inventory).
   `inventory check` builds the workspace once and validates every
   playbook's vars against every host it targets through `--check-vars`,
   printing the vision 10.3 report per failing playbook, `playbooks/x.rs: ok
   (N hosts)` otherwise, and undeclared vars as `warning:` lines. The spike
   `rustible run` subcommand and its `--bin/--package/--host/--escalate`
   flags are deleted. The post-init hint says `rustible playbook run
   playbooks/hello.rs`; the templates' comments already named the M2 and M3
   commands and were left alone (the M4 regeneration test compares them).
   Exit codes: 0; 1 inventory, vars, or build error; 2 a host failed; 3
   usage (clap's own errors included).
3. **Pipeline** (`run.rs`, `describe.rs`, `transport.rs`), vision 5.2 steps
   1 to 9 in order:
   - `cargo metadata` once for the target directory and bin name (so
     `CARGO_TARGET_DIR` and a renamed package work).
   - Describe: `cargo build --features selected --manifest-path
     <root>/Cargo.toml` with `RUSTIBLE_PLAYBOOK=<name>`, dev profile, host
     target, then `<bin> --describe`; the entry is cached at
     `<root>/.rustible/describe/<name>-<sha256 of source length, source,
     lock length, Cargo.lock>.json` and read back without cargo when the key
     matches. The protocol number in the document must match the CLI's.
   - Targets: `inv.select(hosts)` narrowed by `--limit` (see Decisions), each
     `inv.resolve`d.
   - Pre-check: every target's merged vars (`bag_to_json` of the resolved
     bag, then `--var` on top) go to the host-native binary's `--check-vars
     <name>` mode as a JSON array; the problems come back structured and are
     rendered by the inventory module's `format_vars_report` (its input shape
     was reused as is; `run::split_checks` converts). Any error aborts with
     the 10.3 message before anything is built for a target. A playbook with
     `vars_schema: null` skips the check and never needs the binary again.
   - Connect all hosts in parallel: a child process for `connection="local"`;
     for ssh, the CLI launches the ControlMaster itself (`ssh -M -f -N -S
     <tmpdir>/master -o ControlPersist=300 -o BatchMode=yes -o
     StrictHostKeyChecking=accept-new [-p port] [-l user] <ssh_args...> --
     <addr>`) and hands the socket to `openssh::Session::resume`; a failed
     connect fails that host with ssh's own message and the run continues.
   - Probe: one `sh -c 'uname -sm && printf %s\n "$HOME"'`; the triple and
     the absolute home come back together, and every later path is absolute.
   - Build: one `cargo build --profile dist --features selected
     --manifest-path ... --target A --target B` with `RUSTIBLE_PLAYBOOK`;
     artifacts read from `<target_dir>/<triple>/dist/<bin>`, sha256'd.
   - Upload if missing: `test -x '<home>/.cache/rustible/bin/<name with /
     as _>-<sha256>'`, else the bytes stream through `sh -c 'cat > p.tmp;
     chmod 755; mv'` (paths single-quoted).
   - Execute: `[sudo -n | doas -n] [-u <escalate_user>] <abs path> --remote`
     when the describe says `escalate: true` (no `-u` for root; no prefix for
     `escalate="none"`, with a `-v` note), spawned directly (no shell; openssh
     quotes each argument). `Start { run_id, playbook, host: HostInfo { name,
     groups, escalate_user, connection }, vars, check_mode, verbosity }` goes
     down; `Hello` is checked for protocol and playbook name; frames stream
     to the renderer until EOF; exit code and stderr are collected.
4. **Renderer** (`render.rs`). `Pretty` and `stdout_sink` are gone from
   `rustible-sdk`; the SDK keeps `JsonLines`, `Collect`, `FrameSink` and
   gained `Compact`, a one-line-per-event printer the runtime's plain local
   mode uses (`cargo run -- hello` still reads; `--json` gives JSON lines).
   The CLI's `Renderer` buffers everything between `StepStarted` and
   `StepFinished` (`CmdRan` at `-vv`, logs, orchestrator notes) and prints
   the step as one block, so hosts interleave by whole steps; facts (at
   `-v`), sections and top-level logs print as they arrive; a summary table
   (`ok changed would-change skipped failed warnings` per host, or the
   connect error) closes the run. `--json` prints one object per line:
   `{"host", "frame"}` for every `Up` frame, plus `error`, `stderr`, `exit`
   objects from the orchestrator.
5. **Failures** render per vision 14: `` FAILED at `step`: chain `` (the step
   taken from the frame or from the `` step `x`: `` prefix `Ctx::step` adds),
   the command's argv and stderr on their own lines at `-v`. The chain is
   printed once: the `StepFinished` line drops its `note` copy and the
   `Failed` frame prints it; a playbook that swallows the error still gets
   the chain printed from the step. Exit 2 if any host failed (a step, a
   non-zero exit, no `Finished` frame, or a connect/upload/protocol error).
6. **Spikes deleted:** `crates/spike-playbook` (and its workspace member
   line), the `run` subcommand, `RunArgs`, `Pretty`. Docs 02, 03, 04 carry a
   one-line "replaced in M3" note under their title.

**SDK and macro changes.** `registry::Playbook` gained `check_vars: fn(Value)
-> Result<()>`, generated by `#[playbook]` as `from_value::<Vars>(raw).map(|_|
())` (or `Ok(())` without vars). `runtime::main` gained `--check-vars
[<name>]`: stdin is a JSON array of `{ "host", "vars" }`, stdout a JSON array
of `{ "host", "problems": [ { "var", "severity": "error"|"warning",
"message" } ] }`; per host it applies `coerce_scalars_to_lists`, then the
schema walk (`non_flat_vars`, `missing_required`, `type_mismatches` as
errors, `unknown_keys` as warnings), then, when the walk is clean, serde
through `check_vars`; a serde-only failure has an empty `var`. The public
`runtime::{check_vars, check_host_vars, HostVars, HostCheck, VarProblem,
Severity}` are what the CLI parses. `vars::unknown_keys` returns nothing for
a `null` schema (a no-vars playbook warned about every inventory var at
`Start`; found running `hello` against the example inventory).

**Example workspace.** `hello.rs` targets `local`, `cadu/mc.rs` targets
`lab`; group `lab` now carries `vars { package "mc" }` so the done-when runs
`cadu/mc` from the inventory alone.

## Deviations

- **`--limit` narrows instead of replacing** the playbook's hosts. The
  brief's wording admits both; narrowing is Ansible's meaning and cannot
  run a playbook on a host its author did not target. Recorded.
- **`ssh_args` reach ssh verbatim by launching the master ourselves**
  rather than through `openssh`'s builder, which has no way to pass
  arbitrary arguments. `Session::resume` is a documented API; the socket
  lives in a temp dir the transport owns and the master is closed at the
  end of the run (`ControlPersist=300` bounds a leak if the CLI is killed).
- **Built-in `ssh_user` and `port` are not passed to ssh** so
  `~/.ssh/config` wins (vision 5.4); M2's `(ssh default)` sentinel is
  therefore never sent. Recorded.
- **The describe cache holds only the JSON.** The `--check-vars` pre-check
  needs the binary, so on a cache hit the existing debug binary is asked
  `--describe` and reused when it is a selected build of that playbook with
  the identical entry, else rebuilt. The M1 observation about re-linking
  when alternating playbooks stands; a per-playbook artifact cache was not
  added (it would duplicate every dependency's artifacts, vision 9).
- **`inventory check` builds the whole workspace once** (every playbook,
  no `RUSTIBLE_PLAYBOOK`) instead of one selected build per playbook, so a
  broken playbook anywhere fails the check, which vision 9 calls desired.
- **`Compact` was added to the SDK** as the runtime's local-mode printer
  (about 90 lines, no buffering). The lead's preference was JSON lines plus
  a compact fallback; that is what was done. Vision 9's "the `Pretty`
  renderer belongs in the CLI" holds: the buffered renderer exists only
  there.
- **`inventory::validate` is no longer called by the binary** (the
  `--check-vars` mode replaced it as the pre-check). It stays as a tested
  library function; removing it is a follow-up if nobody else wants it.
- **`--json` interleaving** is per frame, not per step (raw frames are the
  point of the flag).
- The `Facts` frame prints at `-v` only; at the default verbosity it was
  noise before the first step.

## Decisions

Recorded in `docs/plan/DECISIONS.md` under rule 2.3 (eleven `[M3]` entries):
`--limit` narrows; built-in `ssh_user`/`port` not passed; the CLI-launched
ControlMaster; exit codes 0/1/2/3; the describe cache and binary reuse;
`--check-vars` structure and `unknown_keys` on a `null` schema; `inventory
check` builds everything once; `Compact` in the SDK; `--json` shape and
`escalate="none"` handling; `package "mc"` in the example's `lab` group;
the Docker harness printing through `Compact` after the merge (below).
