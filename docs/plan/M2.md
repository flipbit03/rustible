# M2: Inventory

**Governing sections of docs/01_VISION.md:** 10 (all of it), 3 (`inventory show`, `inventory check`).
**Depends on:** M1 only for the vars-schema JSON shape (`--describe` output); can be built against a fixture of that JSON.
**Branch:** `m2-inventory`

## Scope

A library module `crates/rustible-cli/src/inventory/` (give `rustible-cli` a
lib target so this is unit-testable; the bin stays `rustible`) plus the two
CLI subcommands.

1. **Parsing** `hosts.kdl` with the `kdl` crate (KDL 2.0). Nodes: top-level
   `vars`, `defaults`, `host`, `group`; inside `group`: `vars`, `members`,
   `host`. Slash-dash nodes are skipped by the parser for free; do not
   re-implement.
2. **Model.** `Inventory { hosts, groups, defaults, vars }`; `Host { name,
   params: HostParams, vars: VarBag, group: Option<String> }`;
   `Group { name, params, vars, members: Vec<String>, hosts: Vec<String> }`;
   `HostParams` with exactly the seven parameters in vision 10.2.1, typed;
   `VarBag = BTreeMap<String, Scalar>` with `Scalar = Str | Int | Float | Bool
   | List(Vec<Scalar>)`. Both `vars { a 1 }` and `vars a=1` forms.
3. **Load-time errors** with file, line, and column: unknown parameter with
   did-you-mean (use a small edit-distance), `addr` on a group or `defaults`,
   missing `addr` on an ssh host, duplicate host or group name, a host defined
   twice, unknown name in `members`, membership cycles, a parameter with the
   wrong type. Collect all errors, do not stop at the first.
4. **Resolution.** `resolve(&self, host) -> Resolved { params, vars, sources }`:
   parameters host, nearest group outward, `defaults`, built-in default; vars
   top-level, groups outermost to innermost (transitive closure through
   `members`), host. `sources` records where each value came from for
   `inventory show`. Sibling-group conflict at equal distance without a host
   override is an error naming both groups and the host (vision 10.3).
   `select("web")` returns the hosts of a group, or the one host, or an error.
5. **Vars validation against a schema.** `validate(resolved_vars, schema_json)
   -> Vec<VarError>` per host, where `schema_json` is what `--describe`
   prints for one playbook (JSON Schema from `schemars`). Required-missing,
   wrong-type, and unknown-var (warning, not error). Format the multi-host
   error exactly as in vision 10.3. Note that the binary re-validates at
   `Start`; this is the pre-check.
6. **CLI.** `rustible inventory show <host>` prints resolved params and vars
   with sources; `rustible inventory check` loads the file and reports all
   errors (exit 1 on any), and, when playbooks exist and `--describe` is
   available (after M3), validates vars for every playbook against every host
   it targets. Until M3, `check` validates the file only.

## Out of scope / do not touch

The SDK, the macro, the run pipeline, `rustible.toml` (M3 reads it; here the
inventory path is an argument defaulting to `hosts.kdl` in the cwd). No
dynamic inventories.

## Done when

```
cargo test -p rustible-cli inventory       # covers vision 10.2.2 example end to end, every error in 10.2.3, precedence, conflicts
rustible inventory show web2               # matches the layout in vision 10.2.2 (sources shown)
rustible inventory check                   # on a file with three planted errors: three messages with line numbers, exit 1
```

## Notes

- KDL 2.0: booleans are `#true`/`#false`; strings quoted; the `kdl` crate
  version must support v2 (check the changelog; v6+).
- Keep comments and formatting untouched: never rewrite the file in this
  milestone (a future `host add` will use the crate's format-preserving edit).
- `escalate` is a parameter (`"sudo" | "doas" | "none"`); `escalate_user`
  defaults to `root`. The word `become` must not appear.
